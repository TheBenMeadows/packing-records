# packing-records

Explicit configurations that improve entries in nine public record tables: seven for packing problems (including spherical codes), one for the harmonic energy of points on a sphere, and one for the Thomson problem. Every file in this repository gives coordinates that a reader can check with the included standard-library checker.

## What counts as an improvement

Each file beats its table entry in the table's own measure, by at least 1e-7 except where stated:

- Grassmannian: the minimum squared chordal distance, n - ||U_i^T U_j||_F^2 over all pairs of orthonormal bases, is at least 1e-10 larger than the table value. The table rounds values down to 10 decimals, so a file that clears this bar beats the true table value and changes its last printed digit. The table's keeper asks for improvements of any size. The value is below the listed upper bound where one is listed (bounds are rounded up). Starred rows and rows noted as proven optimal are excluded. Version 1.0.0 used a stricter bar (a gain of at least 1e-7, and at least 1e-8 below the bound). Its 731 files meet both.
- Game of Sloanes: the coherence, max |<phi_j, phi_k>| over unit vectors, is at least 1e-7 smaller than the leaderboard value and is not below the listed lower bound. Rows marked provably optimal are excluded.
- hsp4, hsp5 and hsp6 (balls in the unit ball of dimension 4, 5 and 6): the feasible radius, min(half the minimum centre distance, 1 - the largest centre norm), is at least 1e-7 larger than the table value for N and for every larger N in the table. (Removing balls from a packing for a larger N gives a packing for N, so a larger-N value is also a valid bound for N.)
- scu: the feasible radius, min(half the minimum centre distance, 1/2 - the largest absolute coordinate), is at least 1e-7 larger than B(N), the largest table value for N or any larger N.
- hsp4, hsp5, hsp6 and scu also: the radius is at least 1e-7 larger than the recorded floor for that N (see below).
- scu, from version 1.2: the floor is the largest of three numbers. The first is the polish floor. The second is the radius reached by adding one sphere at the largest hole of the posted configuration for N - 1 and polishing the result the same way. The third is the largest radius for N or any larger N in the public collection of Moki & Julio (https://github.com/Hashirama1337s/moki-julio-circle-packing, MANIFEST.csv). A cell is kept only when its radius beats that floor by at least 1e-7. `notes` in `cells.csv` records the second and third numbers where they apply.
- Spherical codes: N vectors in R^d whose largest pairwise cosine, after normalising each vector, is at least 1e-11 below the cosine listed at https://spherical-codes.org for (d, N). The table prints 12 decimals, so a file that clears this bar changes its last printed digit. Rows marked proven optimal are excluded. `notes` in `cells.csv` records whether the site flags the row "needs more optimization" (97 of the 529 version 1.3 files). From version 1.5 the bar for a new file is the cosine on the spherical-codes test server just before its upload (see "Version 1.5").
- Thomson problem: N points on the unit sphere whose Coulomb energy, sum_{i<j} 1/|x_i - x_j|, is at least 1e-6 below the minimum for N over every live table (Deeter; the Cambridge Cluster Database Thomson, Thomson2 and Riesz s=1 tables; Wikipedia). For N = 436 only Deeter lists the row. The configuration is a strict local minimum (tangent gradient below 1e-26 and all 2N - 3 = 869 non-rotational Hessian eigenvalues positive, checked separately with mpmath and numpy), and the posted Deeter and CCD configurations for N = 436 polish to an energy 0.0348 higher.
- Harmonic energy: N unit vectors in R^n with energy E = sum_{i<j} |x_i - x_j|^-(n-2), where the exponent n - 2 depends on the dimension. Henry Cohn's table lists the lowest energies known for 4 <= n <= 32 and n+1 <= N <= 64, plus larger cases, from Ballinger, Blekherman, Cohn, Giansiracusa, Kelly and Schurmann (Experiment. Math. 18 (2009)). Their 2021 data set (https://hdl.handle.net/1721.1/130937) gives coordinates and 50-digit energies. A file counts when E is below the smaller of the table energy and the 2021 energy by at least max(1e-9, 1e-12 E). The pair (N, n) must not be a simplex (N = n+1), a cross polytope (N = 2n) or a universal optimum listed at https://cohn.mit.edu/harmonic-optima. In addition, the posted 2021 configuration, polished by L-BFGS and Newton steps, must stay above E plus the same margin. That polished energy is the row's floor in `cells.csv`, and it shows that the file is a different local minimum, not a polish of the posted one. Every stored vector has unit norm to within 1e-20 and at least 25 significant digits per coordinate.

## The polish floor

For each Packomania cell, we took the configuration posted on Packomania and improved it by sequential linear programming on its near-contacts until the step size fell below 1e-13, with three starting trust radii (1e-2, 1e-3 and 1e-4). The best radius reached is the polish floor, recorded in the `floor` column of `cells.csv`. A result that beats the floor by at least 1e-7 is not a local polish of the posted configuration.

The floor is a recorded number. `check/check_all.py` checks the margin over it but does not recompute it. To recompute it, run `floor/polish.py`, which needs numpy, scipy and the posted coordinate archives `hsp4_coords.tar.gz` and `scu_coords.tar.gz` from Packomania placed in `tables/`. The polish runs behind the version 1.4 floors are recorded in `floor/results_2026-11-10.jsonl` (source file, starting trust radius, starting and polished radius). The floor shows that one local method does not reach our value from the posted configuration. It does not prove that the contact graph differs.

## Check the results

Run this command from the repository root. It needs Python 3 and no other packages:

    sh check/check_all.sh

The checker reads every file, recomputes its value with exact rational arithmetic, compares it with `cells.csv` and with the table facts in `tables/`, and checks the rules above. For the harmonic table the squared distances are exact rationals. The energy needs a real power when n is odd, so it is evaluated in decimal at 60 significant digits from the exact squared distances (error below 1e-50), and every harmonic comparison uses a 1e-40 safety margin. It also confirms that every stored Grassmannian basis is orthonormal to within 1e-20, that every stored Game of Sloanes vector has unit length to within 1e-15, that every stored harmonic vector has unit norm to within 1e-20, that each cell appears once, and that the per-table counts match this README. A row with a date in `table_read` is checked against the snapshot of its table read on that date (for example `tables/cohn_grassmannian_2026-11-07.tsv`); rows without one use the original snapshots. The spherical-code check finds the near-maximal pairs in floating point (all pairs within 1e-9 of the largest cosine; float error is about 1e-15) and decides among them with exact integers. The last line of its output is `PASS` or `FAIL`. The checker runs one process per CPU; set `CHECK_WORKERS=1` for a single process. A full run of the version 1.5 tree took 21 minutes with six processes on a 12-core Linux machine that was also running other jobs. Most of that time is in the spherical codes. `check/mutate.py ROOT` plants six defects in copies of the tree and confirms that the checker fails on each. `python3 mutate_v13.py`, run from `check/`, plants six more defects in the version 1.3 checks (spherical codes, Thomson, dated Grassmannian snapshots) and confirms each is caught while the genuine files pass. `python3 mutate_v14.py` does the same for the version 1.4 checks (hsp5, hsp6 and dated Packomania snapshots): 16 defects, three genuine rows. `python3 mutate_v15.py` does the same for the version 1.5 checks (the `status` column, dated harmonic and Grassmannian snapshots, the new spherical snapshots and padded coordinates): 12 defects, nine genuine rows.

`cells.csv` lists every cell with our value, the table value, the margin, the polish floor where one applies, the sha256 of the file, whether the search started from a posted configuration, the author of that configuration, (from version 1.3) the date of the table snapshot the cell was checked against, and (from version 1.5) the file's status with its keeper and the keeper's submission id.

## File formats

- `grassmannian/<m>-<n>-<N>.txt`: line 1 is a comment that starts with `#` and states the cell, our value and the table value. Each following line is one vector of m comma-separated reals. The first n vectors span the first subspace, the next n the second, and so on. The vectors in each subspace are orthonormal.
- `game-of-sloanes/<d>x<n>.txt`: one number per line and no comments, as in the `CurrentBestPackings/` folder of the Game of Sloanes repository. The real parts of all n vectors come first, vector by vector, then the imaginary parts. Every vector has unit length.
- `packomania-hsp4/hsp4-<N>.txt`, `packomania-hsp5/hsp5-<N>.txt`, `packomania-hsp6/hsp6-<N>.txt`: line 1 is the radius, then optional comment lines that start with `#`. Each following line is one centre: index, then 4, 5 or 6 coordinates.
- `packomania-scu/scu<N>.txt`: line 1 is the radius, then comment lines that start with `#`. Each following line is one centre: index, 3 coordinates, then the radius.
- `spherical-codes/<d>-<N>.txt`: line 1 is a comment that starts with `#` and states the cell, our cosine, the table cosine and the attaining pair. Each following line is one vector of d comma-separated reals with at least 20 significant digits.
- `thomson/<N>.txt`: one point per line, x,y,z with 30 significant digits, unit length to within 1e-25.
- `cohn-harmonic/<N>-<n>.txt`: line 1 is a comment that starts with `#` and states the cell, our energy, the bar and the polished energy of the posted 2021 configuration. Each following line is one unit vector of n comma-separated reals with at least 25 significant digits.

## Search methods

The searches were designed and run with AI coding assistants. They were numerical optimization runs: smoothed-maximum (log-sum-exp) descent and Riesz-energy relaxation from random starts, basin hopping, large-neighborhood search that removes and reinserts parts of a configuration, and a final sequential linear-programming polish of the active contacts. For the Packomania tables, 87 of the 108 hsp4 cells of versions 1.0 to 1.2.2 and all 216 scu cells of versions 1.0 to 1.2 started from the configuration posted on Packomania for that N, or for a nearby N. `cells.csv` marks each one in `started_from_posted` and names that configuration's author in `seed_author`. The harmonic configurations came from L-BFGS with a Newton finish, basin hopping from the posted 2021 configuration (perturb, or remove and reinsert 1 to 5 points), and deletion of points from larger configurations in the same dimension. The version 1.3 Grassmannian, spherical-code and harmonic cells came from unattended search lanes seeded from the posted configurations and from our earlier files; the Thomson configuration came from Deeter's posted N = 437 configuration with one point removed, then relaxed into a different basin. The version 1.4 hsp4, hsp5 and hsp6 cells came from unattended search lanes seeded from the files posted on Packomania and from Moki & Julio's files (large-neighbourhood search, smoothed-maximum descent, deletion of balls from larger packings, then a sequential-LP polish); the hsp4 cell for N = 140 and the hsp5 cell for N = 147 came from a large-neighbourhood search started from Moki & Julio's file for that N. The version 1.5 spherical codes, Grassmannian packings and harmonic configurations came from the same kinds of unattended lanes, seeded from the codes posted by each table and from our earlier files, with the spherical batches also polishing every posted code of the test server.
